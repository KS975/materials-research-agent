## 1. 独立优化引擎的类别变量编码仍不完整

**现象**

优化层可以表达和搜索类别变量，例如：

```text
设备 = 设备A / 设备B / 设备C
```

但当前建模模块训练出的 sklearn 模型只接受数值特征。优化层在调用模型前会把类别白名单临时转换为索引：

```text
设备A → 0
设备B → 1
设备C → 2
```

**风险**

对无序类别而言，索引编码会让模型误认为类别之间存在大小和距离关系，例如 `设备A < 设备B < 设备C`，或设备 A 与设备 C 的差异大于设备 A 与设备 B。这种关系对设备、原料类型、供应商、牌号等字段并不必然成立，可能引入假顺序和假距离。

**当前处理**

- 优化请求可以声明 `categorical` 变量和类别白名单；
- 优化、变异、约束检查和结果输出保留原始类别值；
- 进入现有模型前临时使用类别索引；
- 当前 PC_ABS / ABS 真实配方数据以数值特征为主，因此该问题尚未影响已完成的真实数据冒烟测试。

**待补齐**

1. 建模阶段增加类别编码元数据，例如 `ordinal`、`one_hot`、`target_mean`、`native`；
2. ModelArtifact 保存类别编码 Schema、类别顺序、未知类别策略和反编码规则；
3. 优化阶段按模型元数据编码，而不是默认类别索引；
4. 生产模式下，无序类别缺少编码元数据时应拒绝高可信优化并提示重新建模；
5. 为有序类别和无序类别分别补充单元测试与真实数据回归测试。

**优先级**：P0
**相关文件**：

- `engine/optimization/search_space.py`
- `engine/optimization/evaluation.py`
- `engine/modeling/trainer.py`
- `engine/modeling/predictor.py`

## 2. 多目标模型的特征边界不一致时缺少明确安全策略

**现象**

同一优化请求可能加载多个目标模型，例如 `vicat / impact / mfr` 三个模型。不同目标模型的训练样本可能不同，导致同一特征在不同模型中的训练边界不同，甚至没有共同交集。

**当前处理**

- 默认变量构建优先使用所有目标模型的共同训练边界；
- 若共同边界为空，则使用各模型边界的并集，并标记 `allow_exploration=True`；
- 最终可信度依赖 Applicability Domain，`OUT_OF_DOMAIN` 不进入高可信推荐。

**风险**

当前没有把“共同边界为空后回退到并集”显式输出为独立 warning，也没有在候选级结果中标记哪些变量使用了模型训练边界外探索。虽然 AD 能拦截大部分风险，但可解释性和审计能力不足。

**待补齐**

1. 记录每个变量的各模型原始边界、共同边界、实际使用边界和是否发生并集回退；
2. 发生回退时输出 `EXPLORATION_BOUND_USED`；
3. 对使用回退边界的候选降低可信度或移入探索集合；
4. 支持部署配置禁止默认并集回退；
5. 增加多目标模型边界不一致的回归测试。

**优先级**：P1
**相关文件**：

- `engine/optimization/models.py`
- `engine/optimization/search_space.py`
- `engine/optimization/evaluation.py`

## 3. 生产级模型质量门禁还没有部署级优先级

**现象**

优化引擎已有 `ModelQualityGate`，支持 `warn / block`、`min_cv_r2`、`min_test_r2`、`max_cv_rmse`、`max_rmse_to_target_range_ratio`。但当前门禁主要来自请求配置，引擎本身还没有接收部署级质量策略。

**风险**

如果只依赖请求传入 `model_quality_gate`，调用方可能把生产上应阻断的低质量模型降级为 `warn`，继续输出实验性推荐。

**待补齐**

1. 增加部署级质量门禁配置；
2. 实现优先级：部署 `block` 高于部署 `warn`；请求可以把 `warn` 收紧为 `block`，但不能把 `block` 放宽为 `warn`；
3. 在 diagnostics 中记录质量门禁来源；
4. 补充部署策略与请求策略冲突的单元测试；
5. 接入宿主系统配置中心或环境配置。

**优先级**：P0
**相关文件**：

- `engine/optimization/contracts.py`
- `engine/optimization/models.py`
- `engine/optimization/service.py`

## 4. 类别变量的“未使用 / 空值”语义未统一

**现象**

连续添加剂可以用 `0` 表示未使用，但类别变量没有统一的空类别。例如 `助剂类型 = A / B / C` 在候选不使用该助剂时，应使用 `None`、空字符串、专用空类别，还是 one-hot 全 0，目前没有统一契约。

**风险**

互斥约束、总量约束、适用域判断和模型编码可能对“类别变量未使用”产生不同解释，导致同一候选在不同阶段被不同处理。

**待补齐**

1. VariableSpec 显式支持 `none_category`；
2. 约束层统一识别类别变量的未使用状态；
3. 模型编码 Schema 明确未使用类别的编码方式；
4. 输出结果保留业务可读的原始类别值；
5. 增加 mutex、linear_sum 和 one-hot 编码的组合测试。

**优先级**：P1
**相关文件**：

- `engine/optimization/contracts.py`
- `engine/optimization/constraints.py`
- `engine/optimization/search_space.py`

**现象**
